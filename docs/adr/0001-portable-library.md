# ADR-0001：采用可携带的文件夹资料库

- 状态：已接受
- 日期：2026-08-22

## 背景

OpenVideo 当前通过 `OPENVIDEO_LIBRARY_PATH` 指定单个存储目录，并把资源元数据、标记、字幕和分析结果分散保存在资源目录的 JSON 文件中。该方式缺少明确的资料库身份、数据库迁移机制和统一生命周期，也无法提供类似 Eagle 的创建、打开、移动及切换资料库体验。

OpenVideo 需要把用户选择的文件夹初始化成一个完整资料库。资料库应独立于软件安装位置，可以整体移动、复制和备份。软件个性化配置、账户凭据及最近打开记录不属于资料库数据，将通过其他决策单独定义。

## 决策

OpenVideo 采用文件夹级可携带资料库。一个文件夹代表一个完整资料库，单个应用进程同时只打开一个资料库。

### 创建与打开

- 桌面壳负责调用操作系统目录选择器，后端不提供任意文件系统浏览接口。
- 创建资料库时选择一个空文件夹，直接在该文件夹中初始化资料库并保留原名称。
- 打开资料库时必须校验资料库标识、格式版本、数据库版本、写入权限和占用状态。
- 没有有效资料库时进入创建或打开引导，不再隐式创建仓库根目录下的 `library/`。
- 切换资料库前必须停止当前资料库的写入任务、关闭数据库连接并释放占用锁。

### 目录结构

```text
资料库目录/
├─ library.json
├─ openvideo.sqlite3
├─ assets/
│  └─ asset-{uuid7}/
│     ├─ media/
│     └─ artifacts/
├─ cache/
├─ temp/
└─ .openvideo.lock
```

- `library.json` 保存资料库标识、格式版本、显示名称和创建时间，用于识别资料库，不承载业务数据。
- 资料库标识使用 `library-{uuid7.hex}` 格式。
- `openvideo.sqlite3` 保存资料库业务数据。
- `assets/` 保存媒体文件和处理产物，每个资源使用 `asset-{uuid7.hex}` 目录。
- `cache/` 和 `temp/` 可以删除并重新生成。
- `.openvideo.lock` 是运行期占用标记，应用正常关闭时移除。
- 数据库和 JSON 中保存的文件位置必须是相对资料库根目录的路径。用户输入和标识符不得直接拼接成文件路径。

### 数据职责

SQLite 是结构化业务数据的唯一权威来源，负责保存：

- 资源索引与状态
- 标签、标记和资源关系
- 字幕及可查询的时间轴数据
- 下载、转写和分析任务状态
- 处理产物索引
- 资料库级设置

JSON 只保存不适合关系化建模的处理产物，例如模型原始响应、分析中间结果和可复用计算结果。SQLite 仅记录产物类型、相对路径、校验值和生成状态。同一业务字段不得同时由 SQLite 和 JSON 维护，避免双写和冲突。

媒体、缩略图、关键帧、音频等大文件继续保存在文件系统中，不写入 SQLite BLOB。

### 数据库与可靠性

- SQLite 启用外键约束、事务、忙等待和数据库迁移版本。
- SQLite 使用 WAL 模式；WAL 和共享内存文件属于运行期文件。
- 资料库只允许一个写入应用实例，锁文件用于阻止重复打开。
- 复制、移动或同步资料库前必须关闭资料库，确保 WAL 内容已经合并。
- 第一版只保证本地磁盘使用。网络盘和同步盘仅支持应用关闭后的文件同步。
- 数据库备份使用 SQLite Backup API，不能通过直接复制正在使用的数据库完成。
- JSON 处理产物不是数据库备份，不能用于恢复标签、任务等业务数据。

### 兼容策略

当前开发期 `library/videos` 下的 JSON 数据不迁移。新资料库启用后删除旧持久化实现，不保留新旧格式双写或兼容包装。

## 备选方案

### 全局中心数据库

全局数据库便于统一管理多个资料库，但会让资料库依赖当前设备，整体移动和恢复困难，因此不采用。

### 纯 JSON 存储

纯 JSON 易于查看和复制，但跨资源查询、事务、一致性和数据库迁移能力不足，因此不采用。

### SQLite 与 JSON 双写业务数据

SQLite 事务无法与普通文件写入组成原子事务，异常退出后可能出现两份不同的数据，因此不采用。

## 影响

### 正面影响

- 资料库可以整体移动、备份和恢复。
- SQLite 提供事务、查询、索引和迁移能力。
- 文件系统继续承载大型媒体和处理产物，避免数据库膨胀。
- 资料库数据与软件个性化配置边界清晰。

### 负面影响

- 应用需要新增资料库创建、校验、锁定、关闭和切换生命周期。
- 桌面壳需要提供原生目录选择能力。
- 使用中的资料库不能直接复制或由同步软件并发写入。
- 当前开发期数据需要清理后重新创建。

## 后续工作

- 为资料库清单、数据库结构和迁移机制分别定义实现方案。
- 设计桌面壳与后端之间的资料库创建、打开、关闭和切换接口。
- 单独记录软件个性化配置、敏感凭据和最近资料库列表的存储决策。
