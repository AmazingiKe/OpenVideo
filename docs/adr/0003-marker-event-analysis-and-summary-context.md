# ADR 0003：范围标记、焦点选区、事件分析与总结版本

- 状态：已接受
- 日期：2026-08-28

## 背景

局部关注、局部理解和正式文档是三个不同领域。若临时选区、标记分析和 Markdown 总结共用同一数据结构，就无法稳定表达用户意图、判断结果是否过期，也无法追溯一次总结实际消费了哪些输入。

## 决策

### 三个概念严格分离

- **范围标记**是正式业务标记，表示用户认定该时间段是重点内容。
- **In/Out 焦点选区**是每个素材唯一、可持久化的通用 AI 关注范围，不属于任何具体功能，也不是正式标记。允许只保存一端；只有两端完整且 `In < Out` 时才能作为事件分析目标。
- **事件分析**是局部内容的结构化理解结果，来源只能是 `marker` 或 `focus_selection`，不得保存为 Markdown。

焦点选区保存在：

```text
assets/{asset_id}/artifacts/focus-selection.json
```

事件分析采用只追加结果、保留过期历史的契约，保存在：

```text
assets/{asset_id}/artifacts/event-analyses.json
```

SQLite 仅保存两者的可重建查询投影。

### 事件分析生命周期

批量标记分析按每个标记分别生成并自动保存；同一目标可保留多个模型、预设、深度和用户要求产生的结果。每条结果保存目标范围快照、标题、核心结论、关键点、带时间戳证据、预设与版本、深度、用户输入、模型和来源摘要。

标记、焦点选区、转录、时间线或视觉证据变化时，受影响的结果变为 `stale`，但不删除。旧的 `AnalysisMode.MARKERS` 时间线分析流程被删除；全片时间线分析仍走原有审批流程，旧时间线片段不自动转换成事件分析。

标记 Agent 的证据工具可读取当前焦点选区；总结生成器没有读取焦点选区的权限。

### 正式总结的输入白名单

正式总结严格只读取：

1. 完整转录。
2. 全部正式范围标记重点区域及其中的转录原文。
3. 来源为 `marker` 且状态为 `valid` 的事件分析。

`focus_selection` 及由它产生的事件分析不得直接或间接进入正式总结。总结不得重新读取视频、关键帧、OCR、Agent 对话或全片时间线分析。

### 总结角色与生成边界

总结角色参考 Agent 角色定义的表达方式，但使用独立、只读的 `SummaryPreset` JSON，不接入 Agent Runtime。每个角色包含 `preset_id`、标题、说明、提示词、最小上下文容量和版本，且均接受本次用户补充要求。

生成分为两阶段：

1. LLM 基于完整白名单上下文规划文档树。
2. 后端预分配 UUIDv7 文档标识和相对路径，再将同一份完整上下文、当前版本目录与允许路径表交给 LLM 生成正文。

LLM 不能提交任意文件路径。后端只接受允许路径表中的结构化输出，并原子写入。两阶段均使用模型 tokenizer 预检输入和输出预算：已知容量不足时返回结构化 409；容量未知时允许真实尝试并向调用方标记风险。本期不检索、不静默截断，也不自动压缩上下文。

### 多版本总结目录

每次生成追加版本，不覆盖历史版本：

```text
summary/
  manifest.json
  versions/
    summary-version-{uuid7}/
      manifest.json
      index.md
      docs/
      assets/
```

根 manifest 只管理版本列表和 `current_version_id`；每个版本 manifest 管理自己的文档、媒体与生成元数据。文档、媒体、修订冲突、总结 Agent 会话和导出均显式归属 `version_id`。历史版本可切换、编辑、添加子文档并独立导出。

旧单总结目录在读取时执行一次性、幂等、原子迁移：先建立新版本目录，再提交新根 manifest，最后清理旧布局；迁移结束后不保留双路径兼容层。

## 结果

- 用户的正式重点与临时 AI 关注范围不会互相污染。
- 局部分析可重复生成、追溯和失效，而不会覆盖历史。
- 正式总结的输入来源确定且可审计，焦点选区不会影响最终文档。
- 总结生成路径受后端白名单控制，容量不足不会通过静默丢失内容来掩盖。
- 每次生成都是独立版本，历史编辑和导出具有明确归属。
