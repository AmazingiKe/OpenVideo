# ADR 0003：分离标记事件分析与总结文档生成

- 状态：已接受
- 日期：2026-08-28

## 背景

OpenVideo 同时需要支持两种不同粒度的内容理解：用户在标记工作台对局部片段进行快速或深度分析，以及在总结工作台把整段视频整理为 Markdown 文档。

标记表达的是用户关注的位置和范围，不是文档。局部分析结果也需要继续参与后续总结，但如果标记工作台直接生成 Markdown，标记、事件理解和文档表达会相互耦合，难以支持同一标记的多次分析、不同预设以及结果失效判断。

现有时间轴事件表示一条经过审批的全片分析时间轴，默认要求事件不重叠。标记事件分析允许多个选区重叠，也允许同一标记保留多份分析结果，因此不能直接复用单一时间轴事件集合覆盖保存。

## 决策

### 标记只负责定位和局部事件分析

标记工作台不得创建或修改任何 Markdown 总结文档。它只承担以下职责：

- 创建、修改、删除点标记和范围标记，并保存用户设置的 0～5 星重要程度。
- 单选、多选或框选一个或多个时间范围作为分析目标。
- 使用“快速”或“深度”等分析深度执行局部事件分析。
- 使用分析预设与本次用户输入共同构造 LLM 指令。
- 展示、比较和管理结构化事件分析结果。

批量选择多个标记时，任务按每个标记分别生成事件分析，避免把相互独立的关注点合并为无法追溯的单一结果。未绑定标记的临时时间选区也可以生成事件分析，其结果直接保存时间边界，`marker_ids` 为空。

Agent 可以建议标记时间边界，但不得设置或修改用户的重要程度。标记重要程度始终代表用户意图。

### 事件分析是独立的结构化业务数据

事件分析不是 Markdown，也不是总结子文档。每条结果至少保存以下领域信息：

```text
事件分析标识
素材标识
关联标记标识
开始与结束时间
分析深度
预设标识与版本
用户输入
模型标识
标题
核心结论
关键要点
带时间戳的证据
来源内容摘要
状态与创建时间
```

- 所有持久化标识符遵循项目统一 UUIDv7 规则。
- 同一标记可以保留多份由不同深度、预设、用户输入或模型生成的结果，不得默认覆盖旧结果。
- UI 可以把结构化结果渲染为富文本，但不得以 Markdown 字符串作为事件分析的存储契约。
- 事件分析与全片时间轴事件分开保存，允许时间范围重叠。

该业务成果扩展 ADR 0001 的便携资料库布局，权威文件为：

```text
assets/{asset_id}/artifacts/event-analyses.json
```

文件采用带格式版本的固定数据模型和原子写入；SQLite 只保存可重建查询投影。

### 局部事件分析的输入

局部事件分析可以读取当前目标范围内的原始证据，包括转录片段、已有时间轴信息、关键帧、OCR 和画面描述。LLM 的任务指令由以下两层组成：

```text
分析预设：定义稳定的分析目标与输出结构
用户输入：定义本次特别关注的问题
```

预设不得覆盖用户明确输入。LLM 输出必须先校验为事件分析数据模型，再写入业务文件。

### 来源变化会使事件分析失效

每条事件分析保存生成时使用的转录、标记范围和相关证据摘要。出现以下任一变化时，结果标记为过期，而不是静默继续参与总结：

- 关联标记被移动、改为其他范围或删除。
- 对应时间范围内的转录发生修改或重新生成。
- 事件分析依赖的时间轴或视觉证据发生变化。

过期结果可以保留用于追溯，但默认不进入新的总结上下文。用户重新分析后产生新结果，不覆盖旧结果。

### 总结只消费三类内容上下文

总结工作台是唯一生成和编辑 Markdown 文档的模块。生成总结时，内容上下文严格限定为：

1. 当前视频的完整转录。
2. 用户标记的重点区域，包括时间边界、重要程度及对应转录原文。
3. 当前有效的事件分析结果。

用户总结要求、总结预设、详细程度和输出语言属于生成控制参数，不算作额外内容来源。总结生成不得重新读取原始视频、关键帧、OCR、Agent 对话或其他隐式资料；这些证据需要先经过事件分析，才能间接进入总结。

三类上下文按明确区块一次性直接提交给 LLM：

```text
<完整转录>
...

<用户标记重点区域>
...

<事件分析>
...

<用户总结要求>
...

<总结预设>
...
```

完整转录与标记区域中的重复文本是有意保留的关注度信号，必须通过区块名称、标记标识和统一时间戳明确其语义，不得把重复内容伪装成两份独立证据。

### 上下文必须完整且可预检

总结生成默认不使用检索、分块抽样或静默截断。提交前必须估算三类上下文与预期输出所需的 Token：

- 模型上下文足够时，一次性提交全部上下文。
- 模型上下文不足时，阻止生成并提示选择更大上下文模型。
- 只有用户明确选择压缩模式时，才允许生成可检查的压缩上下文；不得在默认流程中自行丢弃转录、标记或事件分析。

每次总结生成保存所使用三类上下文的摘要，使生成结果能够追溯到确定的输入快照。

## 数据流

```text
创建标记或框选时间范围
        ↓
选择分析深度、分析预设并输入本次要求
        ↓
按每个标记或选区生成结构化事件分析
        ↓
校验并保存事件分析，不生成 Markdown
        ↓
完整转录 + 标记重点区域 + 有效事件分析
        ↓
总结预设 + 用户总结要求
        ↓
生成并编辑 Markdown 总结文档
```

## 被否决的方案

- **在标记工作台直接生成 Markdown**：混淆用户关注点、局部理解和最终文档，难以复用事件分析。
- **每个标记只保留一份分析并覆盖旧结果**：无法比较不同深度、预设、指令和模型的结果，也不能追溯历史。
- **把标记事件分析继续写入单一时间轴事件集合**：无法自然支持重叠范围和同一标记的多份结果。
- **总结生成时重新读取视频或视觉证据**：会绕过已经形成的事件分析边界，使生成输入无法稳定复现。
- **默认通过检索或截断减少上下文**：可能遗漏用户明确标记的重点，且用户无法确认实际参与总结的内容。

## 结果

- 标记、事件分析和总结文档形成清晰的单向依赖关系。
- 用户可以对同一视频建立多个重叠选区，并保留多种局部分析结果。
- 总结只基于确定的三类内容上下文，生成过程可复现、可解释。
- 标记或转录变化可以准确识别受影响的事件分析，避免过期结果静默污染总结。
- 需要新增事件分析的数据模型、便携业务文件、SQLite 投影、任务接口和标记工作台 UI。
- 现有标记模式产生的时间轴事件不能自动等同于多版本事件分析；迁移时必须明确转换规则，不得把旧结果无条件复制为有效的新事件分析。
