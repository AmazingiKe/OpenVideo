# ADR 0007：采用渐进式首次总结配图与分层画面选择

- 状态：已接受
- 日期：2026-08-31

## 背景

总结 Agent 首次完成 Markdown 正文后，图片与 GIF 仍需要用户再次要求图文增强，因此第一版笔记无法直接把关键知识点与原视频画面对应起来。

直接让正文模型构造图片路径、猜测时间点或让视觉模型扫描整部视频，会降低证据可靠性，并显著增加长视频的等待时间和在线调用成本。配图还必须遵守 [ADR 0003](./0003-marker-event-analysis-and-summary-context.md) 的正式总结输入白名单，不能让画面检索反向改变正文事实；模型加载、任务恢复和文档并发则继续遵守 [ADR 0005](./0005-agent-runtime-governance.md)。

## 决策

### 首次总结是渐进式图文工作流

首次打开总结页时只初始化空白主文档。当总结 Agent 第一次把空白主文档写成正文且审批成功后，系统自动启动配图任务。正文一经批准即可阅读，配图作为后续阶段渐进补齐，不要求用户再次发起“图文增强”；普通改稿和子文档改稿不重复触发整篇配图。

第一阶段只自动插入静态截图。GIF 的数据契约、已有手动生成能力和文件布局继续保留，但 Agent 不在首次总结中自动选择或生成 GIF。只有静态截图的准确率和体验通过离线验收后，才单独评审自动 GIF。

正文仍由总结 Agent 的证据与审批规则约束。配图是独立的证据后处理层，只能为正文已经表达的内容提供视觉佐证，不得修改正文事实，也不得通过图注引入正文没有依据的新结论。

### 独立配图规划

正文完成后，由独立配图规划器读取：

1. 最终 Markdown 文档树与正文。
2. 本次总结使用的规划模型与正文语言。
3. 全部正式标记及其重要程度。

配图规划器选择真正需要视觉佐证的知识点，并为每个知识点输出结构化媒体槽位。槽位至少包含目标文档、稳定插入锚点、截图目的、证据检索描述和重要性。正文生成和配图规划不得合并为一次模型职责。

正式标记是强优先信号，但不构成必须配图的要求。纯口述内容、普通人物讲话或没有信息价值的画面可以不配图。

### 分层候选检索

每个媒体槽位按以下漏斗寻找候选画面：

1. 并行检索完整转录、OCR、有效事件分析和正式标记。
2. 使用现有本地嵌入与重排模型合并候选，并展开必要的相邻时间片段。
3. 全片继续使用 FFmpeg 轻量场景检测提供粗边界。
4. 只在命中的候选范围内做自适应场景细分，避免重复深度扫描整部视频。
5. 根据片段长度、场景数量和检索不确定性，自适应提取 3 至 7 张候选帧。
6. 在进入在线视觉验证前，剔除黑屏、严重模糊、重复和明显处于转场中的画面。

该结构采用多模态检索先缩小范围、再把有限视觉证据交给模型的原则。相关研究包括 [Video-RAG](https://arxiv.org/abs/2411.13093)、[Adaptive Keyframe Sampling](https://arxiv.org/abs/2502.21271) 与 [FOCUS](https://arxiv.org/abs/2510.27280)。

### 按需视觉向量索引

系统支持完整关键帧视觉向量索引，但不得在应用启动或每次素材导入时默认下载、加载模型或阻塞基础索引。

- 普通配图优先使用已有文本与 OCR 检索结果。
- 当 Agent 判断文字定位不充分或问题主要依赖画面时，可以触发视觉模型下载、加载和增量建索引。
- 用户可以在设置页手动准备视觉检索。
- 已生成的视觉向量持久化并按素材版本失效；模型空闲后可以从内存卸载。
- 下载、加载、建索引范围和可用状态必须在任务中心展示真实进度。

[SigLIP 2](https://arxiv.org/abs/2502.14786) 是首选评测候选，因为它支持多语言图文检索并提供不同规模的模型，但具体检查点、量化方式和资源门槛必须通过本地基准后再固定，不能成为用户需要选择的设置项。

### 在线视觉验证与自动插入

所有准备自动插入的截图都必须经过用户已注册的在线视觉模型验证。本地相似度高不能跳过验证。

视觉验证至少判断：

- 画面是否直接表达目标知识点。
- 关键文字、界面或板书是否清晰可读。
- 画面是否稳定，是否处于转场、遮挡或无意义状态。
- 截图与证据时间范围是否一致。

只有高置信度结果允许自动插入。中、低置信度候选直接跳过，不要求用户逐张审批。配图数量按最终文档树和视觉内容自适应：每个有独立视觉信息的子页面都可以获得自己的配图，长文档也可以覆盖多个不同视觉主题；不设详细程度配额，总量最多 8 张，AI 可以选择更少，甚至不插图。

每张截图必须保存素材版本、来源时间、帧摘要、目标文档、插入锚点摘要、检索证据、视觉模型、提示版本和置信度。持久化标识继续使用带语义前缀的 UUIDv7。图片和图注提供可点击时间证据，能够驱动播放器跳转并高亮对应范围。

### 渐进展示、失败和并发

正文完成后立即显示。待配图位置使用预留宽高比的占位状态，依次展示“正在定位画面”“正在视觉验证”和最终截图，避免内容突然移动。详细候选、工具调用和失败原因默认折叠。

单张截图失败只影响该媒体槽位。系统按既有瞬时错误策略重试后仍失败时跳过该项，保留正文和其他成功截图，不阻塞或回滚整个总结版本。

截图生成期间若文档发生修改，提交前必须读取最新修订，并使用标题路径、目标段落摘要和内容指纹重新定位。只有锚点仍然唯一时才允许插入；无法确认的单项跳过，禁止按旧位置强制写入或覆盖用户内容。

## 本期不采用

- 自动 GIF：保留契约和手动能力，首次总结暂不自动生成。
- 默认加载视觉模型或为所有素材立即建立视觉向量索引：启动和导入成本不可控。
- 视觉模型扫描整部视频：长视频费用、延迟和失败范围过大。
- 只依赖本地相似度自动插图：高检索分数不能证明画面正确。
- 中置信度自动插图或逐张请求用户批准：前者损害准确性，后者增加使用负担。
- 任一媒体失败就阻塞或回滚正文：媒体不是正式总结成功的前置条件。

## 研究与后续方向

[TransNetV2](https://arxiv.org/abs/2008.04838) 记录为复杂转场的按需深度检测候选。当前方案先采用 FFmpeg 粗分段与候选区间自适应细分；只有真实样本证明复杂转场仍显著影响截图准确率时，才评审 TransNetV2 的模型、依赖和加载策略。

[Video ChatCaptioner](https://arxiv.org/abs/2304.04227) 记录为通过语言模型提问、视觉模型回答来丰富画面理解的研究方向。本期不实现 ChatCaptioner，也不把多轮视觉问答加入首次配图链路。

用户满意度、删除或替换行为驱动的自动学习继续按 ADR 0006 延后，不在本期采集或推断。

## 验收

### 自动化验证

- 空白主文档第一次经总结 Agent 成稿并批准后自动进入配图阶段，用户无需再次发起请求。
- 正文失败不会产生媒体；媒体失败不会删除、回滚或阻塞已经成功的正文。
- 每个知识点提取 3 至 7 张候选，最终总结不超过 8 张自动截图。
- 每张自动截图都有高置信度视觉验证结果、完整来源时间和可回跳证据。
- 未配置视觉模型、模型不可用、候选为空和全部验证失败时，系统可靠降级为纯文字总结。
- 文档并发修改时只对最新版唯一锚点提交，不发生旧内容覆盖。
- 视觉模型与索引不会在应用启动时默认加载，手动和 Agent 按需触发均展示真实阶段。
- 窄、中、宽布局以及浅色、深色主题均覆盖加载、部分成功、失败和纯文字状态。

### 离线质量验收

第一阶段使用用户提供的视频建立固定评测集，后续再补充许可清晰的公开样本。每次策略或模型版本变化都记录：

- 截图与目标知识点的相关性。
- 文字、板书、界面和主体的清晰度。
- 核心知识点的视觉覆盖率。
- 重复或近重复截图比例。
- 错误截图进入正文的比例。
- 正文可用时间、配图完成时间、模型调用次数与 API 成本。

高置信度自动插入的正确性是首要发布指标；耗时和成本优化不得通过降低该指标换取。

## 结果

- 用户第一次创建总结即可获得带时间证据的图文笔记，同时正文不必等待全部视觉处理。
- 文字事实生成与画面选择保持职责分离，视觉证据不能反向污染正式总结。
- 长视频只对相关候选范围进行较重处理，启动、本地资源和在线调用保持可控。
- 失败、并发编辑与模型缺失均可局部降级，不增加逐张确认负担。
