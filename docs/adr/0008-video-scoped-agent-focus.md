# ADR 0008：采用视频级 Agent 会话与逐轮聚焦上下文

- 状态：已接受
- 日期：2026-08-31
- 取代：ADR 0004、ADR 0006 中“当前文档参与会话分区”的部分

## 背景

总结工作台过去把 `document_id` 和 `version_id` 写入 Agent 会话上下文。切换章节后，前端会计算出新的会话范围，后端也拒绝同一会话访问其他章节。这让用户看到的“一个视频助手”实际退化为“每章一个助手”，无法连续理解或编辑整条视频。

时间线已有播放头、标记选择、字幕选择和理解范围，总结编辑器也有当前文档与文本选区，但这些状态只在用户手动添加附件时进入运行。Agent 无法稳定理解“这里”“这一章”等指代。反过来，如果直接把界面焦点当成编辑授权，分析请求又可能产生非预期写入。

相关研究和成熟项目给出了一致方向：

- [LAVE](https://arxiv.org/abs/2402.10294) 将视频级理解、Agent 计划和用户批准后的执行结合起来。
- [DirectGPT](https://arxiv.org/abs/2310.03691) 把直接操作状态转成模型上下文，同时保留可操作结果与撤销。
- [ExpressEdit](https://arxiv.org/abs/2403.17693) 用时间、空间和操作引用解释自然语言编辑意图。
- [Generative Timelines](https://arxiv.org/abs/2411.12293) 使用全局时间线承载检索、生成和编辑。
- [OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)、[Kdenlive](https://github.com/KDE/kdenlive) 和 [Blender](https://github.com/blender/blender) 都把全局工程状态、当前选择和可撤销修改分开建模。

## 决策

### 视频是会话边界

用户可见的 Agent 会话只由 `agent_id + asset_id` 分区。章节、总结文档、播放头、面板和选区不得参与会话键计算。切换同一视频内的章节或面板时继续使用原会话；切换视频或内部 Agent 能力时才切换会话。

旧总结会话中保存的 `document_id` 和 `version_id` 可以继续加载，但运行提示词必须移除这些过期字段。它们不再拥有资源授权或默认目标语义。

### 聚焦是逐轮快照

每次发送消息时，前端生成结构化 `focus_context`，与本次运行一起保存。聚焦至少包含：

- 工作区和界面表面，例如时间线、标记面板、转写面板、总结文档或总结选区。
- 用户可见标签，例如“标记面板 · 第 3 章”。
- 播放头、当前章节、完整时间范围。
- 已选择的标记、字幕片段、总结文档和文本位置。

`focus_context` 只用于解释“这里”“这个”和“当前”，不承担以下职责：

- 不限制 Agent 对当前整条视频的读取范围。
- 不替代显式附件中的内容快照。
- 不授予编辑、删除或外部操作权限。

```text
视频级会话
├── 历史消息与已确认结果
└── 本次运行
    ├── 用户请求
    ├── 当前聚焦状态
    ├── 显式上下文附件
    └── 任务输入与检索范围
```

### 分析与编辑分离

意图不明确时必须路由为问答。用户只要求分析、解释或定位时，Agent 可以读取整条视频、总结章节和标记时间线，但不得调用写入工具；回答后可以说明建议，并询问是否生成编辑预览。

只有用户明确要求新增、修改、删除或合并时，才进入编辑工作流：

```text
明确编辑意图
→ 读取目标与证据
→ 生成待审批 Artifact
→ 用户批准
→ 原子应用
→ 可撤销
```

聚焦位置可以作为默认编辑目标，但不能省略目标校验、版本校验、证据门槛或用户批准。

### 整视频工具与精确读取门槛

总结 Agent 可以列出当前视频的全部总结文档，并读取同一视频内任意章节。编辑某个文档前，本次运行必须精确读取该文档；读取 A 章不能满足编辑 B 章的前置条件。跨视频文档和版本不匹配继续由后端拒绝。

时间线 Agent 当前可写范围是标记轨道，包括创建、更新、删除和合并标记。章节分析片段和剪辑轨道结构仍是只读数据；在新增专用工具、冲突合并和撤销契约前，不得向用户声称支持直接修改这些结构。

## 交互要求

- 输入区始终显示“当前视频”、权限模式和当前聚焦标签。
- 聚焦标签在窄屏允许换行，不能溢出或遮挡输入、模型与发送控件。
- 浅色、深色、键盘焦点、ARIA 和 reduced motion 沿用全局设计系统。
- 待审批修改继续使用现有差异预览、批准、拒绝、冲突检测和撤销界面。

## 验收

- 同一视频切换总结章节后，会话标识保持不变。
- 每次运行的提示词和运行事件包含发送瞬间的结构化聚焦状态。
- 提示词明确说明聚焦不是访问边界，也不是编辑授权。
- 总结 Agent 可以列出和读取同一视频内的其他章节。
- 未读取目标文档时，后端拒绝总结修改或媒体建议。
- 跨视频文档和错误版本被拒绝。
- 纯分析请求不会创建写入 Artifact；明确编辑只生成待审批 Artifact。
- 前后端单元测试、类型检查、lint、生产构建和 Storybook 无障碍测试通过。
- 360px 与常规桌面宽度、浅色与深色主题下聚焦状态完整可见。

## 被否决的方案

- 每个章节维护独立 Agent：历史上下文割裂，无法处理跨章节请求。
- 把聚焦当成访问边界：用户必须反复切换或添加附件才能询问全片问题。
- 把聚焦当成编辑授权：分析和指代可能触发非预期写入。
- 把所有章节正文注入每轮提示词：上下文成本高，也绕过按需读取和证据校验。

## 结果

- 用户面对的是一个能够连续理解当前整条视频的 Agent。
- Agent 能理解当前面板和章节，同时仍可按需访问全片。
- 分析、编辑预览和实际写入具有清晰、可测试的权限边界。
- 后续扩展剪辑轨道、章节结构或其他时间线工具时，可以复用同一聚焦与审批契约。
