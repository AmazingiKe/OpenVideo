# ADR 0005：采用确定性权限与可恢复的 Agent 运行治理

- 状态：已接受
- 日期：2026-08-29

## 背景

Agent 可以读取视频证据、修改总结和字幕、生成媒体并调用在线模型。只依赖模型自我判断风险会产生不稳定授权；副作用完成后再独立更新审批状态会产生部分提交；同步线程中的媒体与模型工作也无法通过取消协程真正终止。多 Agent 并行时，基于旧内容生成的结果还可能覆盖较新版本。

## 决策

### 全局权限偏好

权限模式是 OpenVideo 的用户级偏好，必须通过 `openvideo.configuration.OPENVIDEO_CONFIG_DIRECTORY` 保存，禁止写入项目或资料库。首次安装默认使用“智能批准”：

- `请求批准`：所有受控写入和外部副作用都询问。
- `智能批准`：普通、可撤销且证据充分的修改自动执行，只询问确定性策略识别出的高风险操作。
- `完全访问`：减少确认，但不能绕过作用域、版本检查、审计和系统安全边界。

授权支持“仅本次、本次对话、始终允许”。长期授权必须绑定明确工具能力和作用范围，不能保存万能授权。

### 确定性权限引擎

模型只能申请工具和描述意图，不能给自己授权。权限引擎根据工具类别、目标范围、可撤销性、批量规模和外部副作用计算策略。删除、覆盖原内容、批量修改、发布导出和外部服务属于高风险操作。工具声明、运行时前置条件和实际处理器必须使用同一份策略，禁止只在提示词中声明限制。

所有可撤销且证据充分的普通修改可直接执行。每次 Agent 任务形成一个原子版本，要么全部提交，要么完全不修改。低置信度修改不得执行。操作日志记录 Agent、工具、作用对象、授权依据、结果、耗时和版本；敏感正文默认不写入日志，日志仅保存在本地且可清理。

### 乐观并发与最新版本优先

任务开始时记录基础版本，执行期间不锁定用户或其他 Agent。任何写入在提交前重新读取最新版本：

1. 版本未变化时执行原子比较并交换。
2. 版本已变化时，以最新内容重新计算一次。
3. 非冲突修改自动合并。
4. 仍冲突时放弃冲突部分，保留其他安全修改并通知用户。

旧 Agent 不得直接覆盖新版本。历史版本完整保留，用户可查看差异和撤销整个 Agent 任务。

### 调度、取消与恢复

采用自适应调度：前台对话优先，后台索引和长任务使用剩余资源；并发上限由用户配置并遵守模型 API 速率限制。

取消必须传播到在线请求、子进程和本地媒体工作，停止后续步骤，回滚未提交修改并保留安全检查点。禁止仅在界面标记取消而让后台继续运行。暂时失败只对幂等步骤进行有限重试，使用稳定请求键避免重复副作用；超过上限后保存检查点并提供继续能力。

应用退出前持久化任务和检查点。重新打开后恢复安全的索引、检索和工作流步骤；无法确认结果的外部调用先校验状态，不能直接重复执行。

### 模型角色与路由

用户从已注册在线模型中配置“快速文本”“复杂文本”和“视觉”三个角色，视觉角色只有一个活动模型。交互模式为：

- `自动`：快速模型通过结构化路由结果判断是否升级到复杂模型。
- `快速`：用户强制使用快速文本模型。
- `复杂思考`：用户强制使用复杂文本模型。

模式默认值保存在全局用户配置，对话可以临时覆盖。模型路由不能改变权限决策、工具作用域或确定性证据置信度。

## 被否决的方案

- 模型自行批准工具：无法形成稳定安全边界。
- 后完成任务直接覆盖当前内容：会丢失用户或其他 Agent 的更新。
- Agent 工作时锁定文档：长任务会妨碍并行编辑。
- 取消只修改运行状态：仍会消耗本地资源和在线费用。
- 无限自动重试：可能重复收费或长期占用任务队列。

## 结果

- 用户默认很少被打断，但高风险副作用仍由不可绕过的程序策略控制。
- 多 Agent 可以并行读取和计算，提交时不会用旧版本覆盖新内容。
- 取消、失败和重启具有真实、可测试的状态语义。
- 审批、业务副作用、版本与审计记录能够作为一个事务验收。

## 实现校准

截至 2026-08-29，大语言和视觉模型只接受在线 API 配置，本地算力仅用于转录、OCR、关键帧和检索。所有模型请求共用有界调度器：前台助手优先，后台任务为前台保留容量；`408`、`409`、`425`、`429` 和服务端瞬时错误遵循 `Retry-After` 与指数退避，最多重试两次。Agno 仅在尚未发布事件时重试，避免重复工具调用或文本副作用。
