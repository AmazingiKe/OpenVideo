# ADR 0010：采用 Agno 会话上下文与紧凑工具活动展示

- 状态：已接受
- 日期：2026-09-01
- 细化：ADR 0002 中 OpenVideo 与 Agno 的会话职责边界
- 扩展：ADR 0006 的工具活动渐进披露规则

## 背景

OpenVideo 已使用 Agno 执行 Provider 消息、工具调用和模型循环，但每次运行仍由 OpenVideo 从持久化事件重新拼接用户与助手消息，并在超过字符上限时直接删除较早消息。这个实现能够形成基础多轮对话，却存在三个问题：

- 字符数不等于模型 Token，用统一字符阈值无法可靠适配不同模型。
- 超限后直接删除旧消息会丢失目标、约束、决定和已经完成的工作，没有形成可继续使用的摘要。
- OpenVideo 与 Agno 同时承担部分上下文职责，后续需要自行维护历史顺序、工具消息兼容和压缩边界。

工具调用在界面中使用“工具活动”标题、状态 Badge、嵌套列表和结果卡片。普通调用也占用较大的垂直空间，状态装饰比最终答案更醒目，不符合 ADR 0006 要求的渐进披露，也不适合面向普通用户的轻量助手。

产品需要的是连续、自然且安静的对话体验，而不是向用户暴露专业 Agent 的上下文、Token 和执行拓扑管理界面。

## 决策

### Agno 独占模型上下文管理

使用项目已经依赖的 Agno 2.9 作为唯一模型会话上下文管理库。Agno 采用 Apache-2.0 许可证，并原生提供会话历史、会话摘要、最近运行限制和工具结果压缩。本期不再引入 LangGraph、Mem0 或其他第二套 Agent 框架。

OpenVideo 的视频级 `session_id` 直接作为 Agno `session_id`。同一个会话中的后续运行只提交当前轮输入，由 Agno 负责加载历史；新建会话生成新的 UUIDv7，并与其他会话完全隔离。

Agno 会话启用以下能力：

- `add_history_to_context=True`：继承同一会话历史。
- `num_history_runs=3`：保留最近三轮原始对话，维持短期细节。
- `enable_session_summaries=True`：维护较早对话的滚动摘要。
- `add_session_summary_to_context=True`：将摘要与最近原文共同加入模型上下文。
- `compress_tool_results=True`：由 Agno 压缩冗长工具结果。
- `max_tool_calls_from_history`：只保留理解后续问题所需的最近工具调用，避免历史工具噪声淹没对话。

具体管理器使用 Agno 的 `SessionSummaryManager` 和 `CompressionManager`。OpenVideo 可以配置所用模型和公开阈值，但不得重新实现摘要、Token 估算、历史裁剪或工具结果压缩算法。

删除 `AgentRuntime._compress_context`、`MAX_CONTEXT_CHARACTERS` 以及运行前从事件派生完整模型消息的持续路径。已有事件到 Agno 会话的首次导入只用于迁移旧会话，不得演变成第二套长期上下文管理器。

参考：

- [Agno Sessions](https://docs.agno.com/sessions/overview)
- [Agno Session Summaries](https://docs.agno.com/sessions/session-summaries)
- [Agno Context Compression](https://docs.agno.com/compression/overview)
- [Agno 开源仓库](https://github.com/agno-agi/agno)

### 业务会话与模型会话分工

OpenVideo 继续负责：

- ADR 0008 定义的视频级会话身份和逐轮聚焦快照。
- 运行状态、取消、超时、权限、审批和撤销。
- 业务事件、运行指标、SSE 恢复和用户可见聊天记录。
- 当前视频、显式附件、任务输入与检索范围。

Agno 负责：

- 同一会话的模型消息历史。
- 会话摘要的生成、更新和注入。
- 历史轮次与历史工具调用的上下文限制。
- 当前工具循环中的冗长结果压缩。

逐轮 `focus_context`、附件和检索范围仍是发送瞬间的输入。它们通过 Agno `additional_input` 以 `add_to_agent_memory=False` 注入当前运行，不进入后续模型历史或会话摘要；Agno 只持久化用户可见消息和最终回答。旧聚焦不得成为新一轮的当前焦点或编辑授权。会话摘要也不得把模型推断升级为已验证项目记忆；ADR 0004 的证据、版本和权限要求继续有效。

### 使用 Agno SQLite 会话存储

使用 Agno 官方 `AsyncSqliteDb` 保存模型会话，数据库属于当前资料库的业务数据，不属于应用配置。增加 Agno SQLite 适配器所需的 `sqlalchemy` 和 `aiosqlite` 依赖。

Agno 会话存储与 OpenVideo 业务事件存储职责不同，可以使用独立表或独立数据库文件，但必须共享同一个 `session_id`。界面不提供“保存上下文”操作；会话连续性是默认行为，并应在应用重启后保持。

升级前已经存在的 OpenVideo 会话，在 Agno 尚无对应会话时，从持久化的用户消息和最终回答执行一次幂等导入。工具原始返回、模型推理内容、流式增量和过期聚焦不进入迁移历史。

### 自动压缩与单一手动入口

自动摘要和工具结果压缩默认开启。用户无需选择摘要模型、历史轮数、Token 阈值或压缩策略。

会话操作菜单只提供一个“压缩上下文”入口，用于通过 Agno 的公开会话摘要接口强制刷新当前会话摘要。短会话无需压缩时返回无操作结果；失败不阻断当前对话，也不删除原始聊天记录。

自动或手动压缩完成后，界面最多展示一条弱提示，例如“已整理较早的对话内容”。不展示上下文百分比、Token 曲线、摘要版本、快照树或可编辑记忆面板。OpenVideo 事件只记录压缩状态和触发来源，不复制 Agno 保存的摘要正文。

### 工具调用使用紧凑活动行

普通工具调用不再渲染为大卡片或“工具活动”总卡片，而是直接出现在对话时间线中：

```text
✓ 检索视频证据                         找到 6 项
✓ 检查关键画面                         4 帧
⟳ 生成标记变更预览                     处理中
```

每个活动行包含状态图标、面向用户的动作名称和简短结果。遵循以下规则：

- 完成状态使用弱化的语义颜色，不使用醒目 Badge。
- 运行中显示 Spinner 和进行时文案。
- 失败状态突出错误，并默认展开可执行的错误信息。
- 参数和原始返回默认隐藏，点击整行后按需展开。
- 重复调用逐次显示，保留真实执行顺序，不按工具名称合并成抽象统计。
- 窄面板允许结果换行或隐藏次要摘要，不能产生水平滚动。
- 需要用户决定的 Artifact、审批、冲突和撤销继续使用完整卡片，不与普通工具活动混用。

实现复用现有 shadcn Accordion、Button、Spinner、Message、Marker 和 Lucide 图标。颜色、间距、字号、圆角、焦点和动效只使用全局语义 Token；不增加仅服务于工具行的新颜色或局部 CSS 变量。

## 实施顺序

1. 为 Agno 配置异步 SQLite，并把 OpenVideo `session_id` 传入每次 Agno 运行。
2. 开启会话历史、最近三轮、会话摘要和工具结果压缩。
3. 增加旧会话的一次性幂等导入，验证新旧会话隔离。
4. 删除 OpenVideo 自研的消息拼接和字符截断压缩路径。
5. 增加轻量的手动压缩 API、状态事件和会话菜单操作。
6. 把工具活动改成紧凑单行，并保留审批类卡片。
7. 补充后端、前端和 Storybook 回归验证。

## 验收

- 同一会话能够回答上一轮提供的信息，应用重启后仍能继续。
- 新会话、不同视频和不同内部 Agent 能力之间不会串入历史。
- 当前轮聚焦与附件不会被旧聚焦覆盖，也不会绕过读取、证据和审批门槛。
- 长会话由 Agno 使用摘要与最近三轮原文，不再由 OpenVideo 按字符直接删除旧消息。
- 冗长工具结果由 Agno 压缩；OpenVideo 不包含自研摘要或 Token 裁剪实现。
- 自动摘要失败时仍可使用最近历史完成普通对话，并向用户提供非阻断提示。
- 工具调用在成功、运行、失败、重复调用和长返回场景下均保持紧凑、可展开和顺序准确。
- 键盘、焦点、ARIA、对比度和 reduced motion 通过检查。
- 360px、常规桌面宽度以及浅色、深色主题均无溢出或状态丢失。
- 后端 Ruff、Agent 单元测试与 API 测试，以及前端 lint、类型检查、Vitest、生产构建和 Storybook 构建全部通过。

## 被否决的方案

- **继续维护 OpenVideo 自研上下文裁剪器**：需要自行处理 Token、摘要更新、工具历史和 Provider 差异，与已经采用 Agno 的架构重复。
- **只发送最近若干轮并直接丢弃旧消息**：实现简单，但会失去长期目标、约束和已经完成的决定。
- **每轮发送完整历史**：短期准确，长会话的延迟、成本和上下文溢出不可控。
- **再引入 LangGraph 或 Mem0**：会形成第二套会话与持久化模型，增加依赖和职责冲突，当前需求没有足够收益。
- **向用户展示完整上下文仪表盘**：增加学习成本，也会让普通聊天被专业 Agent 概念淹没。
- **把所有工具调用渲染为卡片**：垂直空间和视觉权重过大，用户难以快速定位最终回答和待处理操作。
- **完全隐藏工具活动**：长任务失去反馈，失败和等待状态难以理解。

## 结果

- 同一会话默认连续，新会话保持明确隔离。
- 长对话的摘要、历史和工具结果压缩由开源库统一维护。
- OpenVideo 保留业务安全、证据和交互控制，不再复制 Agent 框架职责。
- 普通工具调用退居为安静、可核验的过程信息，最终回答和待审批操作重新成为视觉重点。
- 增加异步 SQLite 依赖和摘要模型调用；摘要生成会产生少量额外延迟与在线模型费用，需要通过测试确认不会阻塞首字流式体验。
