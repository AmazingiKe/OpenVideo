# 索引、检索与自动配图算法重构记录

## 取舍与依据

本轮保持现有本地模型、精度和 SQLite 存储，优先消除重复工作并验证证据质量。

| 方法 | 本项目采用的部分 | 边界 |
| --- | --- | --- |
| [AKS，CVPR 2025](https://arxiv.org/abs/2502.21271) | 有限帧预算同时考虑重点与时间覆盖 | 本地标记、场景和最远点启发式；没有复现论文的视觉语义评分 |
| [AdaRD-Key，2025](https://arxiv.org/abs/2510.02778) | 避免固定时间排除窗口丢掉邻近重要事件 | 不实现论文的最大体积优化，不引入额外视觉模型 |
| [RRF](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) | 以 `k=60` 融合词法和语义候选排名 | 融合值只用于候选排序，不解释为概率 |
| [MMR](https://aclanthology.org/X98-1025/) | 在相关候选内惩罚内容冗余 | 使用词项 Jaccard 相似度；相关门槛先于多样性 |
| [Qwen3-Reranker](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) | 独立交叉编码相关性评分 | 不把模型分数宣称为校准后的回答正确率 |
| [FFmpeg 多输入输出](https://ffmpeg.org/ffmpeg.html) | 四个独立精确寻址输入共享进程启动成本 | 每个时间点仍独立解码，限制同时打开的解码器数量 |
| [FFmpeg select 源码](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/f_select.c) | 读取 `lavfi.scene_score`，一次扫描复用多个阈值 | 元数据分数保留六位小数，极接近阈值时可能与原始浮点比较不同 |

视觉向量以内容 SHA256、模型版本和维度决定复用。文件改名或仅修改修改时间无需重新推理；模型变化、内容变化和损坏向量需要重算。构建失败保持旧缓存，查询排除已经变化的帧。每个素材独立通知等待者，消费者取消不会停止其他消费者共享的构建。

## 可复现实测

### 媒体处理

Windows、本机 530.603 秒 H.264 视频、3840×2160。全片均匀分布 12 个采样时间，交替运行前后方案三轮，取中位数；所有输出位于临时目录，没有修改原素材或资料库。

| 步骤 | 原方式 | 重构后 | 耗时降低 | 结果对照 |
| --- | ---: | ---: | ---: | --- |
| 12 帧抽取 | 5.3333 秒 | 3.8743 秒 | 27.4% | 三轮解码后 RGB 最大像素差均为 0 |
| 50.060–80.060 秒局部扫描 | 1.1697 秒，3 次扫描 | 0.3732 秒，1 次 | 68.1% | 候选时间点一致 |
| 225.271–255.271 秒局部扫描 | 0.6601 秒，2 次扫描 | 0.3306 秒，1 次 | 49.9% | 候选时间点一致 |
| 400.482–430.482 秒局部扫描 | 1.5220 秒，3 次扫描 | 0.3840 秒，1 次 | 74.8% | 候选时间点一致 |

这些是单步测量，不能当作完整索引总耗时的加速比。全片场景扫描仍需解码，本次同一视频扫描耗时 36.392 秒。

另做一次硬件解码探测：保留当前 CPU 缩放和场景滤镜，仅添加 `-hwaccel cuda`，耗时从 CPU 的 38.426 秒变为 67.272 秒，两者均检测到相同的 161 个切点。因此本轮没有强制开启 GPU 解码。这个单次结果只适用于本机、此 H.264 样本和当前滤镜链，不能推断其他硬件、编码格式或全 GPU 滤镜链的性能。

在 `apps/backend` 目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_media_indexing.py "视频路径" --repeats 3 --output "结果路径.json"
```

### 检索

固定合成评测集包含 50 条证据、30 个问题，覆盖中英文、词序变化、近义干扰和跨来源证据。神经模式使用已安装的 Qwen 模型，没有调用在线模型。前后使用同一评测集；重复查询的结果顺序一致。

| 模式 | 指标 | 原方式 | 重构后 |
| --- | --- | ---: | ---: |
| 词法 | Recall@3 | 0.0667 | 0.9000 |
| 词法 | MRR@3 | 0.0667 | 0.8667 |
| 词法 | nDCG@3 | 0.0667 | 0.8647 |
| 神经及重排 | Recall@3 | 0.8833 | 1.0000 |
| 神经及重排 | MRR@3 | 0.9667 | 0.9833 |
| 神经及重排 | nDCG@3 | 0.8942 | 0.9850 |

这组小规模合成数据参与了策略迭代，不是独立测试集，也不能推断通用准确率。仅扩大词法召回时神经 Recall@3 曾退到 0.8333，证明扩大候选必须与排序校准配合。

另外对实际资料库执行只读抽查：408 条证据、两个视频、12 个根据现有正文编写的问题，前三项结果与预期时间窗口重叠的数量从 10/12 提升到 11/12。这个指标只检查定位，不代表答案正确。“列表 ADT 应该支持哪些操作”仍未命中正确窗口，需要继续研究长章节分块与检索表达。

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_text_retrieval.py --output "词法结果.json"
.\.venv\Scripts\python.exe scripts/evaluate_text_retrieval.py --neural --output "神经结果.json"
```

评测脚本只构建临时资料库；神经模式要求模型已经安装。运行总时长包含模型加载、索引及重复查询，不应直接解释为单次查询延迟。

## 质量与可靠性

- 统一 12 帧的初稿在真实 OCR 对照中损失较多文字，未采用为最终策略。最终保留最多 12 帧的基础预算，按未覆盖场景增加代表帧，每章最多 36 帧。密集切点合成案例的抽帧数量从 119/306 限制到 36，四个时间分区仍有覆盖；无切点但含 20 个聚集标记时保留优先级最高的 8 个和 4 个全章上下文点。
- 真实 FFmpeg 像素测试覆盖乱序时间、重复时间、多批次和取消路径；独立寻址与批量寻址一致。
- 30fps 合成视频中的 0.1 秒短场景仍被采到；只有一帧的瞬时事件不保证保留，当前选择器没有帧率或实际展示时间信息。
- 视觉索引覆盖新增素材、重名内容去重、增量修改、删除、模型变化、损坏向量、原子失败回滚、构建时内容变化、消费者取消及按素材完成通知。
- 自动插图继续要求候选和最终截图两次高置信度验证，检索分数本身不授权插图。

### 真实 OCR 覆盖对照

对上述 4K 视频固定既有 10 个章节，不添加标记，使用同一套已安装的 RapidOCR 模型，重新识别原缓存帧与新选帧。模型和转录不变。结果按章节去重后汇总：

| 方案 | 帧数 | OCR 文本行数 | 与原方案完全相同的文本行数 |
| --- | ---: | ---: | ---: |
| 原缓存帧 | 279 | 863 | 863 |
| 统一最多 12 帧的初稿，已放弃 | 119 | 513 | 344 |
| 最终场景自适应预算 | 174 | 752 | 492 |

最终方案减帧 37.6%，比统一 12 帧保留更多场景文字。由于采样时点改变、字幕变化和 OCR 切行误差，文本行数与完全相同行数都不是语义准确率。部分短暂文字仍未保留，例如一个片段中的“可变帧率”标签；不能宣称视觉证据覆盖无损。完整转录保留，自动配图继续按局部证据重新抽帧并验证。

本次单轮 OCR 用时为原帧 150.905 秒、新帧 92.796 秒，但包含首次模型初始化，且与回归测试有资源竞争，因此仅作为诊断记录，不纳入稳定加速比。

## 后续优先级

1. 用“列表 ADT 操作”失败样例评估长章节分块与查询表达，建立独立留出集后再改召回策略。
2. 对字幕无法覆盖的短暂文字评估局部 OCR 补充，尤其是同一镜头内变化的界面标签；提高全局帧上限不等同于完整文字覆盖。
3. 针对首次导入的 4K 全片扫描，测试包含缩放在内的完整硬件处理链，并验证不同编码格式与无 GPU 的回退行为。
